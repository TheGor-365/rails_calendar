# RC-038 Slice F — unapproved synthetic revision delta preview

This is an **in-memory** comparison of two independently owner-reviewed fictional requirement candidate snapshots for the same workspace/client/intake. No document content or revision is written; there are no new routes, migrations, exports, background work, storage reads, external AI requests or billable calls. Production and real-client files remain forbidden.

The service \`Studio::SyntheticRequirementRevisionDiff\` requires **exact source descriptors and comparison digests for both snapshots**. It regenerates their source graphs and owner-triage receipts via Slices A–E; permission and content fingerprints are rechecked, not accepted from a previously supplied report. It does not trust previously generated status values. It uses *exact source locator + candidate type* as an **ephemeral coordinate**, and the bounded normalized segment's SHA256 only for deciding whether the claim changed across whole-source revisions. Neither the claim text nor its hash is returned.

Classifications: \`unchanged_unverified\`, \`changed_unverified\`, \`newly_retained_unverified\`, \`no_longer_retained_unverified\`. The last means missing from the explicitly retained candidate set, **not proof that the client removed a requirement or permitted deletion**. Moved or renumbered coordinates may appear as separate additions/removals; this is not semantic diff, stable requirement identity, or acceptance. Diff is blocked when either review is incomplete, has needs-information/unknown/conflict outcomes or partial evidence coverage; no deletion/supersession is ever applied.

Every row requires independent owner/client review. The result always reports \`automatic_deletion=false\`, \`automatic_supersession=false\`, \`requirement_approved=false\`, \`scope_approved=false\`, \`client_confirmed=false\`, \`document_generation_allowed=false\`, \`persisted=false\`, \`external_calls=0\` and \`billable_usd=0\`.

Run \`bin/rails test test/services/studio/synthetic_requirement_revision_diff_test.rb\` on the isolated localhost \`ruby_calendar_test\`. Exact-HEAD CI, security checks and owner local tests are acceptance gates. Actual immutable encrypted artifact revisions, client verification, legally reviewed consent, monitored malware scanning, backup/restore and release approval remain future work. Never upload real client documents.
