# Rails Calendar AI Workspace — i18n Phase 1
Updated 2026-11-13. Draft branch off PR #45. No production writes.

## Goal and architecture
English (`en`) is the canonical source and default. Russian (`ru`), Armenian (`hy`), Spanish (`es`) are first-class supported UI locales. Namespaces use `config/locales/{locale}/{i18n,nav,auth,flash,client,mail,ai,marketing}.yml`. The same keys exist in all four languages. `config.i18n.fallbacks = true` preserves legacy untranslated views during subsequent phases.

Public and owner/client layouts use `html lang` and common `shared/locale_switcher`; explicit POST /language under Rails CSRF persists validated preference in a signed HttpOnly SameSite=Lax cookie. Only same-origin relative paths can be passed as redirect return targets, with fallback to /services. Per-request `I18n.with_locale` avoids cross-request state leakage. Language is independent of login/session reset and never changes roles or access. URLs remain fixed for now.

## Coverage
- Client registration, email-code verification, privacy QA notice; owner login, local owner bootstrap and legacy administrator login; OTP email subject and message, result/validation notices, client empty home.
- Shared account nav, app nav and public site nav; marketing content, public SEO descriptions and four service cards.
- AI UI placeholder keys defined but no Grok execution/prompt translation or auto-approved content. Existing calendar/consultations/quiz/project-intake labels retain original strings until reviewed later; fallback is not a claim of complete translation.
- The public URL remains one canonical URL; hreflang / SEO locale-specific paths, templates with multiple-form RTL support, and localization of dates/numbers/time zones are **not shipped**. Armenian is left-to-right; UTC calendar remains UTC.
